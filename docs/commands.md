# Command reference

Generated from the argparse tree in `scripts/mythify_parser.py` by
`python3 scripts/build_commands_doc.py`. Do not edit this file by hand:
change the parser, regenerate, and commit both. `python3 scripts/lint.py`
fails when this file is stale.

`mythify` is the installed launcher. From a clone, run
`python3 scripts/mythify.py` with the same arguments.

Global options: `mythify --version` prints the version, and `-h` or
`--help` after any command prints its help. Exit codes: 0 success, 1
refusal or failure, 2 a recorded unverified verdict, 64 a usage error.

## Commands

- `init`: Create ./.mythify with subdirectories and an empty memory.json.
- `protocol`: Protocol copy checks.
- `status`: Orient: active plan, outcome, map, and product, evidence breakdown, and attention items.
- `history`: Show a read-only verification history.
- `report`: Show a chat-ready live work report from durable Mythify events.
- `route`: Choose the next workflow route from prompt text and durable state.
- `prompt`: Render read-only workflow prompt packets.
- `map`: Chart and work a wayfinding decision map.
- `product`: Plan a product: problem, user, outcomes, non-goals, bets, risks.
- `lineage`: Attach and inspect typed artifact lineage.
- `review`: Record blast-radius safety cases and prove them.
- `loop-fit`: Advise whether a task should be a loop, supervised, or done directly.
- `outcome`: Run outcome-driven loops with verifier and iteration budget.
- `plan`: Manage plans: create, import, add-step, verify, list, show, switch, archive.
- `step`: Update a step's status; completed requires RESULT plus passing verify run.
- `memory`: Persistent key-value memory: set, get, clear.
- `lesson`: Record and list lessons (project store, or global with --global).
- `logs`: Maintain Mythify jsonl logs.
- `verify`: Verification: run a command (executed) or record a claim (attested).
- `reflect`: Record a structured reflection as JSON or flags.
- `summary`: Full session report: plans, outcomes, maps, products, memory, lessons, evidence, reflections.
- `mcp`: Serve Mythify commands as MCP tools over stdio.


## report

```text
mythify report [--since {last,start}] [--format {chat,json}] [--recent RECENT] [--cursor CURSOR] [--peek] [--mark]
```

Chat-ready live work report: plan creation, step updates, verification records, and reflections from durable state. By default it advances a cursor so repeated calls with --since last only show new events; use --peek to leave the cursor unchanged.

Options:

- `--since {last,start}`: Event window to report: last cursor or start of state. Defaults to last.
- `--format {chat,json}`: Output format: chat or json. Defaults to chat.
- `--recent RECENT`: Maximum events to show. Defaults to 8.
- `--cursor CURSOR`: Report cursor name. Defaults to default.
- `--peek`: Do not advance the report cursor.
- `--mark`: Advance the report cursor to the latest event without showing old events.

## map

Chart work that is too big for one session as a decision map: a destination, decision tickets on a blocking frontier, fog for what cannot be specified yet, and an out-of-scope register. Tickets resolve decisions, not build slices. A human-in-the-loop ticket is refused without --human-input, which Mythify records but cannot attribute, so an agent must never write it itself; a task ticket with a verify command needs a passing executed run.

### map create

```text
mythify map create [--name NAME] [--notes NOTES] [--fog FOG] [--json] destination
```

Create a decision map with a destination, optional notes, and any fog you can already see, then set it active.

Arguments:

- `destination`: What reaching the end of this map looks like.

Options:

- `--name NAME`: Map name. Defaults to a slug of the destination.
- `--notes NOTES`: Domain, skills, and standing preferences for this effort.
- `--fog FOG`: A question you can see coming but cannot yet state sharply. Repeatable.
- `--json`: Print JSON.

### map list

```text
mythify map list [--json]
```

List maps with active marker, open and frontier counts, and status.

Options:

- `--json`: Print JSON.

### map show

```text
mythify map show [--json] [name]
```

Show the map body: destination, notes, decisions so far, the frontier, claimed and blocked tickets, fog, and out of scope.

Arguments:

- `[name]`: Map name. Defaults to active.

Options:

- `--json`: Print JSON.

### map ticket

```text
mythify map ticket --type {research,prototype,grilling,task} [--question QUESTION] [--mode {afk,hitl}] [--blocked-by BLOCKED_BY] [--verify VERIFY] [--from-fog FROM_FOG] [--map MAP] title
```

Add a decision ticket. The type fixes whether a human is in the loop: research and task run AFK, prototype and grilling are HITL. Only task tickets may choose their mode.

Arguments:

- `title`: Ticket title. This is its name; reports refer to it by name.

Options:

- `--type {research,prototype,grilling,task}`: research, prototype, grilling, or task. Required.
- `--question QUESTION`: The decision this ticket resolves. Defaults to the title.
- `--mode {afk,hitl}`: Only for task tickets: afk when the agent can drive it alone, hitl otherwise.
- `--blocked-by BLOCKED_BY`: Ticket ids this ticket waits on, comma separated or repeated. Repeatable.
- `--verify VERIFY`: Executable proof for a task ticket's done-condition.
- `--from-fog FROM_FOG`: Fog patch id this ticket graduates.
- `--map MAP`: Map name. Defaults to active.

### map claim

```text
mythify map claim [--by BY] [--map MAP] id
```

Claim an open, unblocked ticket so concurrent sessions skip it. One decision ticket per claimant at a time; research tickets run in parallel.

Arguments:

- `id`: Ticket id such as T1.

Options:

- `--by BY`: Claimant. Defaults to MYTHIFY_MAP_CLAIMANT or session.
- `--map MAP`: Map name. Defaults to active.

### map verify

```text
mythify map verify [--map MAP] [--timeout TIMEOUT] id
```

Run the ticket's verify_command and record the executed evidence with the map and ticket context. The resolve gate reads the latest executed run of that command recorded since the claim, so a passing run here satisfies it and a failing one cancels an earlier pass. CLI-only.

Arguments:

- `id`: Ticket id such as T1.

Options:

- `--map MAP`: Map name. Defaults to active.
- `--timeout TIMEOUT`: Timeout in seconds. Default 300.

### map resolve

```text
mythify map resolve --answer ANSWER [--gist GIST] [--human-input HUMAN_INPUT] [--out-of-scope] [--fog FOG] [--scope-out SCOPE_OUT] [--map MAP] id
```

Close a claimed ticket with the decision it reached. HITL tickets require --human-input; task tickets with a verify command require the latest executed run of it since the claim to pass. Use --out-of-scope for a ticket that turns out to sit past the destination.

Arguments:

- `id`: Ticket id such as T1.

Options:

- `--answer ANSWER`: The decision this ticket reached. Required.
- `--gist GIST`: One-line index entry. Defaults to the answer.
- `--human-input HUMAN_INPUT`: What the human actually decided. Required for HITL tickets.
- `--out-of-scope`: Rule the ticket past the destination instead of recording a decision.
- `--fog FOG`: New fog the answer surfaced. Repeatable.
- `--scope-out SCOPE_OUT`: Work the answer ruled past the destination. Repeatable.
- `--map MAP`: Map name. Defaults to active.

## product

Product planning from a product manager or director lens: the problem in the user's words, one primary user, at most five measurable outcomes, non-goals, bets with kill criteria and human deciders, and the four product risks. The record is material. product check lints readiness per stage; approve and decide need the human's words; promote turns an approved bet into a plan; measure records an outcome's metric as executed evidence.

### product create

```text
mythify product create --problem PROBLEM --user USER [--stage {prototype,pre-launch,growth,enterprise}] [--appetite APPETITE] [--name NAME] title
```

Create a draft product with the problem in the user's words and one primary user, then set it active. The stage sets how strict product check is: prototype, pre-launch, growth, or enterprise.

Arguments:

- `title`: Product or initiative title.

Options:

- `--problem PROBLEM`: The problem in the user's words, without naming the solution. Required.
- `--user USER`: The one primary user this product serves. Required.
- `--stage {prototype,pre-launch,growth,enterprise}`: Product stage; later stages add readiness rules. Defaults to prototype.
- `--appetite APPETITE`: How much time or effort this is worth.
- `--name NAME`: Product name. Defaults to a slug of the title.

### product outcome

```text
mythify product outcome --metric METRIC --target TARGET [--baseline BASELINE] [--target-source {user,cited,decided,hypothesis}] [--measure MEASURE] [--product PRODUCT] statement
```

Add an outcome with a metric and a target, optionally a baseline, where the target came from, and a measure command that reads the metric. A product keeps at most five outcomes.

Arguments:

- `statement`: The change in the world this outcome describes.

Options:

- `--metric METRIC`: The metric that moves. Required.
- `--target TARGET`: The target value for the metric. Required.
- `--baseline BASELINE`: The metric's current value, when known.
- `--target-source {user,cited,decided,hypothesis}`: Where the target came from: user, cited, decided, or hypothesis.
- `--measure MEASURE`: Shell command that reads the metric and exits 0 only when the target is met.
- `--product PRODUCT`: Product name. Defaults to the active product.

### product non-goal

```text
mythify product non-goal --reason REASON [--revisit-when REVISIT_WHEN] [--product PRODUCT] text
```

Record what this product will not do, why, and what would reopen it.

Arguments:

- `text`: What is out.

Options:

- `--reason REASON`: Why it is out. Required.
- `--revisit-when REVISIT_WHEN`: The trigger that would reopen it.
- `--product PRODUCT`: Product name. Defaults to the active product.

### product bet

```text
mythify product bet --outcome OUTCOME --kill KILL [--decider DECIDER] [--decide-by DECIDE_BY] [--priority PRIORITY] [--product PRODUCT] hypothesis
```

Add a bet: a hypothesis linked to the outcomes it should move, the result that would stop it, the human who decides, and when. Lower priority numbers go sooner.

Arguments:

- `hypothesis`: What we believe and will build to test it.

Options:

- `--outcome OUTCOME`: Outcome id this bet should move, such as O1. Repeat or comma separate. Required. Repeatable.
- `--kill KILL`: The result that stops this bet. Required.
- `--decider DECIDER`: The human who decides continue, pivot, or stop.
- `--decide-by DECIDE_BY`: Decision date, as YYYY-MM-DD.
- `--priority PRIORITY`: Priority; lower goes sooner. Defaults to after the last bet.
- `--product PRODUCT`: Product name. Defaults to the active product.

### product risk

```text
mythify product risk --kind {value,usability,feasibility,viability} [--mitigation MITIGATION] [--validation VALIDATION] [--product PRODUCT] text
```

Record one of the four product risks: value (will the user want it), usability (can the user work it), feasibility (can we build it), or viability (does it work for the business).

Arguments:

- `text`: The risk.

Options:

- `--kind {value,usability,feasibility,viability}`: value, usability, feasibility, or viability. Required.
- `--mitigation MITIGATION`: How the risk is reduced.
- `--validation VALIDATION`: How we will learn whether the risk is real.
- `--product PRODUCT`: Product name. Defaults to the active product.

### product check

```text
mythify product check [--json] [name]
```

Deterministic readiness lint. Every stage needs a problem, a user, at least one outcome with metric and target, a non-goal, and bets linked to existing outcomes. pre-launch adds target sources and a value risk; growth adds measure commands and bet deciders; enterprise adds decide-by dates, risk mitigations, and all four risk kinds. Exits 0 when ready and 2 when gaps remain.

Arguments:

- `[name]`: Product name. Defaults to the active product.

Options:

- `--json`: Print JSON.

Arguments:

- `[name]`: Product name. Defaults to the active product.

Options:

- `--human-input HUMAN_INPUT`: What the human actually said when approving. Required.

## review

Record blast-radius safety cases and prove them.

### review blast-radius

```text
mythify review blast-radius --status {pass,warn,fail} --path PATH --safety-fact SAFETY_FACT [--proof-depth {1,2,3}] [--risk RISK] [--cleared CLEARED] [--merge-command MERGE_COMMAND] [--name NAME]
```

Create a material-only blast-radius safety case.

Options:

- `--status {pass,warn,fail}`: Review verdict. Required.

- `--cleared CLEARED`: Cleared-risk JSON object; repeat as needed. Repeatable.
- `--merge-command MERGE_COMMAND`: Cheapest executable proof to run before merge.
- `--name NAME`: Review name. Defaults to a generated slug.

### review prove


## outcome

Manage an outcome loop: define success, run verifier checks, track iteration budget, and tell the host whether to retry, stop, or report success.

### outcome start

```text
mythify outcome start --success SUCCESS --verify VERIFY [--metric METRIC] [--metric-floor N] [--max-iterations MAX_ITERATIONS] [--allowed-paths ALLOWED_PATHS] [--frozen-paths FROZEN_PATHS] [--supersede REASON] [--agent AGENT] [--max-cost MAX_COST] [--escalate-after ESCALATE_AFTER] [--name NAME] [--json] goal
```

Start an outcome loop with a concrete verifier and iteration budget.

Arguments:

- `goal`: Outcome goal.

Options:

- `--success SUCCESS`: Human-readable success criteria. Required.
- `--verify VERIFY`: Shell command that verifies the outcome. Required.
- `--metric METRIC`: Optional shell command that emits a metric.
- `--metric-floor N`: Minimum metric score required for success. Requires --metric; a green verifier with a score below the floor does not succeed.
- `--max-iterations MAX_ITERATIONS`: Maximum verifier iterations before the outcome fails. Default: `3`.
- `--allowed-paths ALLOWED_PATHS`: Comma-separated scope paths, checked post-hoc via git. outcome run fails an iteration that changes files outside the scope; outcome check names those files in its next action without failing.
- `--frozen-paths FROZEN_PATHS`: Comma-separated paths the loop must never touch (e.g. tests/), relative to the project root. An absolute path must be inside the root, and a path that names no existing file or directory is refused. Enforced in every mode; a change under a frozen prefix stops the loop. Files are hashed on disk at start and on every check, so git index flags and exclude files cannot hide a change; files under a frozen directory that the repository's .gitignore files ignore are not covered.
- `--supersede REASON`: Retire the currently active outcome into this one, recording the reason and lineage. Without it, a second start is refused.
- `--agent AGENT`: Command that attempts the work each iteration (an agent CLI or a script). When set, outcome run drives the loop autonomously. The command may print MYTHIFY_COST=<n> to report its cost.
- `--max-cost MAX_COST`: Cost ceiling for the loop. Each iteration costs what the agent reports via MYTHIFY_COST, else one unit; the loop fails when the cumulative cost reaches this ceiling.
- `--escalate-after ESCALATE_AFTER`: outcome run stops and hands back to a human after N consecutive failed verifications. outcome check does not count them.
- `--name NAME`: Outcome name; defaults to a slug of the goal.
- `--json`: Print JSON.

### outcome run

```text
mythify outcome run [--notes NOTES] [--timeout N] [name]
```

Autonomously run an outcome started with --agent: each iteration runs the agent command, then the verifier, records evidence, and repeats until the outcome is met, the iteration or cost budget is spent, the scope is violated, or the escalation threshold of consecutive failures is reached. Each iteration and one cost unit are charged before the agent starts, so a killed or timed-out run still spends them. Bounded and evidence-gated. Exits 0 on success, 2 otherwise. CLI-only.

Arguments:

- `[name]`: Outcome name; defaults to the active outcome.

Options:

- `--notes NOTES`: Notes stamped on each iteration.
- `--timeout N`: Timeout in seconds for the agent and each verifier command. Default: `300.0`.

### outcome check

```text
mythify outcome check [--notes NOTES] [--audit] [--timeout N] [--json] [name]
```

Run the verifier and optional metric for the active or named outcome. Exits 0 when the outcome is verified, 2 when it is not yet met or failed.

Arguments:

- `[name]`: Outcome name; defaults to the active outcome.

Options:

- `--notes NOTES`: Notes for this iteration.
- `--audit`: Re-run a finished outcome's verifier without mutating its history; a red run marks the outcome's evidence stale.
- `--timeout N`: Timeout in seconds for each command. Default: `300.0`.
- `--json`: Print JSON.

- `[name]`: Outcome name; defaults to the active outcome.

- `--json`: Print JSON.

### outcome stop

```text
mythify outcome stop --reason REASON [--json] [name]
```

Mark an outcome stopped and clear the active pointer when it matches.

Arguments:

- `[name]`: Outcome name; defaults to the active outcome.

Options:

- `--reason REASON`: Why the loop is being stopped. Required.
- `--json`: Print JSON.

## plan

Manage plans: create, import, add-step, verify, list, show, switch, archive.

### plan create

```text
mythify plan create [--steps STEPS] [--name NAME] [--parent PARENT] goal
```

Create a plan and set it active. Without --steps the plan starts empty; add steps with plan add-step.

Arguments:

- `goal`: What the plan should accomplish.

Options:

- `--steps STEPS`: JSON array of step objects: [{"title": str, "success_criteria": str (optional), "verify_command": str (optional)}]. A step's verify_command is the executable proof of its done-condition; run it with plan verify.
- `--name NAME`: Plan name; defaults to a slug of the goal.
- `--parent PARENT`: Parent artifact kind:id. Repeat as needed. Repeatable.

### plan import

```text
mythify plan import [--source {godplans,godaudits}] [--name NAME] [path]
```

Convert godplans or godaudits checkbox tasks into a Mythify plan. Each step keeps the task's exact Verify command, and completion requires that verification to pass while the step is in progress. Every task imports as a pending step, including one already checked in the artifact: a checked box is not executed evidence. Mythify never edits the artifact: checkbox flips stay with the executing agent per the artifact's embedded rules.

Arguments:

- `[path]`: Artifact path; defaults to discovering .godplans/PLAN.mdx or .godaudits/AUDIT.mdx (with .md fallbacks) at the project root.

Options:

- `--source {godplans,godaudits}`: Artifact kind when the path does not make it obvious.
- `--name NAME`: Plan name; defaults to the artifact name plus the source kind.

### plan add-step

```text
mythify plan add-step [--criteria CRITERIA] [--verify VERIFY] [--plan PLAN] title
```

Append a step (id = max + 1) to the named or active plan.

Arguments:

- `title`: Step title.

Options:

- `--criteria CRITERIA`: Success criteria for the step.
- `--verify VERIFY`: Executable command that proves the step is done; run it with plan verify.
- `--plan PLAN`: Plan name; defaults to the active plan.

### plan verify

```text
mythify plan verify [--plan PLAN] [--timeout TIMEOUT] id
```

Execute the step's verify_command, mark the step in progress, and record the executed verification against that step. On success the strict-evidence gate is satisfied, so step ID completed will pass. Exits 0 when verified, 2 when the command fails, 1 on usage errors.

Arguments:

- `id`: Step id (1-based integer).

Options:

- `--plan PLAN`: Plan name; defaults to the active plan.
- `--timeout TIMEOUT`: Timeout in seconds for the verify command. Default: `300.0`.

### plan list

```text
mythify plan list
```

List plans with the active marker, per-plan progress, and the archived count.

### plan show

```text
mythify plan show [name]
```

Show full detail of the named or active plan. Exits 1 if not found.

Arguments:

- `[name]`: Plan name; defaults to the active plan.

### plan switch

```text
mythify plan switch name
```

Set the active plan pointer. Exits 1 if the plan is not found.

Arguments:

- `name`: Plan name.

### plan archive

```text
mythify plan archive [name]
```

Move the named or active plan file to plans/archive/, clearing the active pointer if it pointed there. On filename conflict in the archive, a timestamp is appended.

Arguments:

- `[name]`: Plan name; defaults to the active plan.

## step

```text
mythify step [--plan PLAN] id status [result]
```

Update step ID to STATUS (pending, in_progress, completed, failed, skipped). completed and failed require the RESULT argument: evidence or a failure description. By default, completed also requires a passing verify run since the step started; a later failing run of the same command cancels an earlier pass. Set MYTHIFY_REQUIRE_VERIFIED_STEP=0 only for legacy prose-only completion. Prints the next pending step afterward.

Arguments:

- `id`: Step id (1-based integer).
- `status`: One of: pending, in_progress, completed, failed, skipped.
- `[result]`: Evidence or failure description; required for completed and failed.

Options:

- `--plan PLAN`: Plan name; defaults to the active plan.

Options:

- `--all`: Clear every memory entry.
